# Qwen Corpus Loss Analysis (2026-08-14)

## Scope

This report evaluates LiteNN CPU AOT against llama.cpp on a frozen, teacher-forced public text slice after the Qwen2
NeoX RoPE correction. It measures the negative log likelihood of the actual next token under identical token histories,
so greedy near ties cannot alter later contexts. No machine-specific model, cache, or artifact path is retained.

The model under test is Qwen2.5-Coder 14B Q4_K_M. The campaign uses three repository-authored MIT-licensed samples:
technical prose, C++ source, and structured reasoning. Each sample contributes 64 target tokens after one unscored
context token, for 192 scored positions. Text bytes, provenance, normalization policy, and per-sample SHA-256 digests
are frozen in `example/gguf/qwen_corpus_loss_slice.json`; token ids are regenerated by the model tokenizer.

## Alignment Contract

Both runtimes expose `litenn.teacher_forced_logits.v1` manifests with `captureBoundary=pre-target`. Each artifact must
declare a contiguous decision step, position, and target token id. Prompt and target ids must match exactly across
runtimes. Missing, duplicate, shifted, fallback, sparse, or non-finite artifacts fail integrity before scoring.

The llama.cpp adapter now has a dedicated `teacher-forced-logits` command. A two-step real-model control reproduced
the existing natural greedy decision-step 0 and 1 text logits byte-for-byte, including matching SHA-256 digests. This
proves that the new capture records the distribution before feeding each target rather than the old `decode-logits`
post-token boundary. Independent synthetic tests also reject post-target and one-token-shifted manifests.

## Predeclared Gate

The following thresholds were fixed before the real corpus run:

| Check | Required | Measured | Result |
| --- | ---: | ---: | --- |
| Cases | >= 3 | 3 | PASS |
| Target tokens | >= 192 | 192 | PASS |
| Valid cases | 3 / 3 | 3 / 3 | PASS |
| Aggregate cross-entropy regression | <= 0.02 nats | -0.00891644 nats | PASS |
| Relative perplexity regression | <= 2% | -0.887681% | PASS |
| Worst sample cross-entropy regression | <= 0.10 nats | 0.00105719 nats | PASS |

Negative deltas mean LiteNN assigns slightly higher probability to the frozen target tokens than llama.cpp. They are
not interpreted as a quality improvement; the acceptance claim is only that no material regression was measured.

## Runtime And Artifact Cost

The complete campaign took 222.7 seconds. Tokenization took 10.0 seconds total, the three llama.cpp reference processes
took 62.1 seconds, and the three LiteNN processes took 112.2 seconds. The remaining roughly 38.4 seconds covers full-
vocabulary text parsing, NLL evaluation, report construction, and orchestration overhead.

The 192 reference files occupy 0.549 GiB and the 192 LiteNN files occupy 0.522 GiB, for 384 logits files and 1.072 GiB
total. This independently confirms that the planned compact indexed Float32 container is needed before routine CI use.
Per-process timings include model/tool startup and diagnostic text output and are not steady-state decode throughput
evidence.

## Conclusions

1. The teacher-forced corpus gate passes all predeclared coverage, integrity, aggregate-loss, relative-perplexity, and
   worst-sample thresholds.
2. The measured aggregate CE delta is `-0.008916 nats` and relative perplexity delta is `-0.887681%`; there is no
   evidence of a material LiteNN language-model quality regression on this frozen slice.
3. The fixed-trajectory explanation step-33 Jensen-Shannon outlier does not justify projection or model-math changes.
   Its residual remains documented, but same-input sub-layer localization is not promoted without broader quality
   evidence.
4. Post-NeoX functional acceptance is now supported by natural generation, full fixed-reference distributions, and
   teacher-forced corpus loss. Normal cache-hit throughput under the accepted variance gate remains open and separate.
5. The current panel is a deterministic regression gate, not a claim of broad benchmark coverage. The later task-
   quality panel should expand domains and sequence lengths without weakening this frozen baseline.

## Next Work

1. Run normal logits-only cache-hit throughput outside checkpoint/full-vocabulary diagnostic builds.
2. Replace text logits with a compact indexed Float32 container and preserve random access, metadata, checksums, and
   atomic publication.
3. Add the planned small task-quality panel after throughput acceptance, retaining the corpus slice as a stable
   low-cost semantic regression control.
